## 🧱 Repository facts

- The site is static HTML, CSS, and browser JavaScript. It does not use a client-side router or an application framework.
- There are seven distributed JavaScript bundles and eight custom element tags. The bumper bundle registers both the single bumper and the three-bumper cluster.
- Each bundle is intended to work by itself. Its file contains the shared runtime, that control's artwork, recorded sound data, and component-specific behavior.
- When several bundles are loaded on the same page, the first bundle initializes `window.PinballKit`; later bundles reuse it.
- The root `package.json` is a private tooling manifest. It is not a published npm package.
- The root package currently declares `UNLICENSED`, and there is no root `LICENSE` file. Redistribution permissions should not be inferred.

## 🧭 Documentation maintenance

Keep these pages aligned with the repository:

1. Verify behavior in the actual component bundle and its generated component guide before documenting a public API.
2. Update [tools/spec.mjs](../tools/spec.mjs) for component descriptions, demo markup, attributes, and generated component documentation.
3. Run `npm run docs` after changing the component specification. Run `npm run build` after changing the shared core or assets.
4. Run `npm run check` before committing.
5. Update these technical pages when architecture, scripts, routes, test coverage, or deployment workflows change.

The technical pages are manually maintained. They are not generated by `tools/docs.mjs`, so review their links and claims as part of a documentation change.
