### 1. Toggle (`toggle`)

- **Implementation source:** [`toggle/toggle.js`](../toggle/toggle.js)
- **Standalone bundle:** [`toggle/toggle.js`](../toggle/toggle.js)
- **Custom element tag(s):** `<pinball-toggle>`
- **Runtime family:** Original mechanical (PinballKit, WebGL scene, artwork and recorded audio)
- **Attributes:**
  - `checked`: Boolean; default Absent (off); Observed after connection. Presence means on; removing it means off.
  - `disabled`: Boolean; default Absent; Observed after connection. Makes the host inert and prevents interaction.
  - `mode`: String enum; default `live`; Observed after connection. `live`, `plates`, or `3d`. The latter two are alternate rendering modes, not separate controls.
  - `label`: String; default `Toggle`; Read on connection. Accessible-name fallback when `aria-label` and `aria-labelledby` are not supplied. It is not observed for later changes.
  - `name`: String; default Omitted; Form configuration. Form field name. Set it before using the control in a form.
  - `value`: String; default `on`; Form configuration. Submitted while checked. An empty string also falls back to `on` in the current implementation.
- **Properties:**
  - `checked` (boolean, Read/write): Current logical switch value.
- **Methods:**
  - `toggle()`: Flip the logical checked state programmatically. It does not emit user-interaction events.
- **Events:**
  - `change`: CustomEvent, `detail: { checked: boolean }`. Fires for user activation, including a drag that resolves to a new checked state. It does not fire for programmatic state changes.
  - `input`: Plain `Event`; **no `detail` payload**. Fires immediately after `change` for the same user toggle. Read `event.target.checked` or use the `change` payload.
- **Pointer and touch:** Tap or click the switch button, or drag the ball along the lane and release. A drag resolves to the nearest end and commits the checked state.
- **Keyboard:** The internal control is a native button with `role="switch"` and `aria-checked`. Space and Enter activate it.
- **Forms:** The control is form-associated. With `name` set, it submits no value while off. While on, it submits the `value` attribute, or `on` when that attribute is absent or empty. Form-associated custom elements require browser support for `ElementInternals`.
- **Styling:** Set `--pb-size` to change the control height (36px by default). Set `--pb-page` to a six-digit hex colour matching the page background so the chrome reflections blend into the page. `--pb-focus` changes the visible keyboard-focus outline.
- **Reduced motion:** The shared runtime honours `prefers-reduced-motion` by moving the ball directly to the final state. The lamp still reflects the checked state.
- **References:** [API guide](../toggle/README.md) · [Live demo](../toggle/)

**Implementation notes and limits:**
- The visual `mode` attribute switches rendering style only. Do not use it as application state.
- Programmatic `.checked` changes and `toggle()` update the form value and rendering but deliberately do not emit `change` or `input`.
- The `input` event is not a `CustomEvent` and has no `detail`; use `change.detail.checked` when you need a payload.
- The `label` attribute is read on connection rather than observed live. Set it before the element is inserted, or provide `aria-label` / `aria-labelledby`.

### 2. Slider (`slider`)

- **Implementation source:** [`slider/slider.js`](../slider/slider.js)
- **Standalone bundle:** [`slider/slider.js`](../slider/slider.js)
- **Custom element tag(s):** `<pinball-slider>`
- **Runtime family:** Original mechanical (PinballKit, WebGL scene, artwork and recorded audio)
- **Attributes:**
  - `value`: Number; default `0`; Observed after connection. Initial numeric value; clamped to the configured range and snapped to the step grid.
  - `min`: Number; default `0`; Observed after connection. Lower bound.
  - `max`: Number; default `100`; Observed after connection. Upper bound. The effective maximum is never lower than `min`.
  - `step`: Number; default `1`; Observed after connection. Value increment. Use a positive step.
  - `disabled`: Boolean; default Absent; Observed after connection. Makes the host inert and prevents interaction.
  - `label`: String; default `Slider`; Read on connection. Accessible-name fallback. It is not observed for later changes.
  - `name`: String; default Omitted; Form configuration. Form field name. Set it before form submission.
- **Properties:**
  - `value` (number, Read/write): Current numeric value.
  - `min` (number, Read-only getter): Effective lower bound from the `min` attribute.
  - `max` (number, Read-only getter): Effective upper bound, not lower than `min`.
  - `stepSize` (number, Read-only getter): Effective increment from the `step` attribute.
- **Methods:**
- None documented.
- **Events:**
  - `input`: CustomEvent, `detail: { value: number }`. Fires each time a user pointer or keyboard interaction changes the numeric value.
  - `change`: CustomEvent, `detail: { value: number }`. Fires after a changed pointer drag ends, or immediately after a keyboard adjustment changes the value.
- **Pointer and touch:** Press anywhere on the track to move the thumb there, or drag the ball. The numeric value updates as the thumb moves.
- **Keyboard:** The focusable internal slider has `role="slider"`. Arrow Right/Up increase by `step`; Arrow Left/Down decrease by `step`; Page Up/Down move by one tenth of the range (at least one step); Home and End go to the bounds.
- **Forms:** The control is form-associated. With `name` set, it submits the current number as a string. Form-associated custom elements require browser support for `ElementInternals`.
- **Styling:** Set `--pb-size` to change height (36px by default); width follows the photographed track's fixed aspect ratio. Set `--pb-page` to a six-digit hex page colour and `--pb-focus` to change the visible focus outline.
- **Reduced motion:** The shared runtime honours `prefers-reduced-motion`; the thumb snaps to the final value while the value and lamp state remain available.
- **References:** [API guide](../slider/README.md) · [Live demo](../slider/)

**Implementation notes and limits:**
- The track always has ten lamps. They visualize fill along the range; they do not represent the configured step count.
- The value is snapped to the nearest step relative to `min`, with decimal precision rounded to six places.
- The `label` attribute is read on connection rather than observed live. Set it before the element is inserted, or provide `aria-label` / `aria-labelledby`.
- Use a positive `step`; the component does not expose a separate `step` property, only the `stepSize` getter.

- **Runtime family:** Original mechanical (PinballKit, WebGL scene, artwork and recorded audio)
- **Attributes:**

  - `flipped` (boolean, Read-only getter): Whether the `flip` attribute is present.

- **Pointer and touch:** Drag the knob back and release it after the ball has dropped in front of the tip. A pointer tap only twitches the knob; it is not a send action. A release before the full pull does not emit `send`.

- **References:** [API guide](../plunger/README.md) · [Live demo](../plunger/)

**Implementation notes and limits:**
- The ball travels across the page above surrounding content before it is removed. Allow sufficient open space around the control.
- The public convenience method documented for application use is `fire()`; `send` is the completion event.
- Reduced motion is not honoured for this component yet.
- The travelling ball is drawn above page content and crosses the page before it disappears.

  - `max`: Number; default `99`; Observed after connection. Upper bound; the effective maximum is never lower than `min`.
  - `step`: Integer; default `1`; Observed after connection. Increment, rounded to an integer and kept at least 1.
  - `digits`: Integer; default Automatic; Observed after connection. Force 2 to 4 drums. Otherwise the count is derived from `max`, with at least two drums and at most four.
  - `label`: String; default `Stepper`; Observed after connection. Accessible-name fallback for the spinbutton.
  - `name`: String; default Omitted; Form configuration. Form field name.
  - `disabled`: Boolean; default Absent; Observed after connection. Makes the host inert and prevents interaction.

  - `value` (number, Read/write): Current whole-number value.

  - `digitCount` (number, Read-only getter): Current number of score-reel drums, from 2 to 4.
- **Methods:**
  - `increment(n = 1)`: Increase by `n` configured steps. Programmatic calls do not emit `input` or `change`.
  - `decrement(n = 1)`: Decrease by `n` configured steps. Programmatic calls do not emit `input` or `change`.
- **Events:**
  - `input`: CustomEvent, `detail: { value: number }`. Fires when a user interaction changes the value, including each auto-repeat step while a flipper is held.
  - `change`: CustomEvent, `detail: { value: number }`. Fires for each user-initiated step that changes the value, including hold-to-repeat.
- **Pointer and touch:** Press a plus/minus flipper, hold it for repeated steps, or drag the score reels vertically. Flipper presses focus the spinbutton control.
- **Keyboard:** The focusable internal control has `role="spinbutton"`. Arrow Right/Up and `+`/`=` increase; Arrow Left/Down and `-`/`_` decrease. Page Up/Down move by roughly one tenth of the configured range (at least one step); Home/End go to the bounds. Holding an increment/decrement key repeats.

- **Styling:** Set `--pb-size` to change height (52px by default); the housing keeps its fixed aspect ratio. Set `--pb-page` to a six-digit hex page colour and `--pb-focus` to change the visible focus outline.
- **Reduced motion:** The shared runtime honours `prefers-reduced-motion`; the drums and flippers snap to their final state while the value remains available.
- **References:** [API guide](../stepper/README.md) · [Live demo](../stepper/)

**Implementation notes and limits:**
- The default range is 0 through 99. Keep `min` non-negative because the visual drum renderer has no minus sign.

- The visual score reel has no minus sign. Use a non-negative `min` even though the numeric range attributes accept numbers.
- The drum display supports at most four places.

### 5. Drop targets (`targets`)

- **Implementation source:** [`targets/targets.js`](../targets/targets.js)
- **Standalone bundle:** [`targets/targets.js`](../targets/targets.js)
- **Custom element tag(s):** `<pinball-targets>`
- **Runtime family:** Original mechanical (PinballKit, WebGL scene, artwork and recorded audio)
- **Attributes:**
  - `items`: Comma-separated strings; default `EMAIL,PUSH,TEXT,CALLS`; Observed after connection. Target labels. Empty entries are removed; at most four labels are used. If no usable labels remain, the default list is restored.
  - `checked`: Comma-separated indexes or labels; default None; Observed after connection. Initial checked set. Indexes are zero-based (0 to 3); label matching is case-insensitive.
  - `label`: String; default `Bonus targets`; Observed after connection. Accessible name for the checkbox group.
  - `name`: String; default Omitted; Form configuration. Form field name.
  - `disabled`: Boolean; default Absent; Observed after connection. Makes the host inert and prevents interaction.
- **Properties:**
  - `checked` (boolean[], Read/write): Array of checked states, in the current item order. Assigning a non-array is ignored.
  - `selected` (string[], Read-only getter): Labels for currently checked items, in item order.
- **Methods:**
  - `toggle(index, user = false)`: Invert one item. Pass `user: true` to emit the user-style `change` event.
  - `setChecked(index, checked, user = false)`: Set one item. The default programmatic call is silent.
  - `resetAll(user = false)`: Clear all checked items. With `user: true`, emits one summary `change` event using `index: -1` and `item: null.
- **Events:**
  - `change`: CustomEvent, `detail: { index, item, checked, selected, allChecked }`. Fires for a user toggle. `selected` is a snapshot of checked labels after the update. `resetAll(true)` emits a summary event with index -1.
  - `bonus`: CustomEvent, `detail: { selected: string[] }`. Fires when the final target impact completes the cleared bank in normal-motion mode. It is tied to the impact animation.
- **Pointer and touch:** Activate a target to check or uncheck it. The `checked` property updates immediately; the target drop animation follows.
- **Keyboard:** Each target is a native button with `role="checkbox"`. Space and Enter activate the focused target. Arrow Left/Right move focus between targets and wrap at either end.
- **Forms:** The control is form-associated. With `name` set, it submits the checked labels joined by commas (for example `EMAIL,PUSH`). Form-associated custom elements require browser support for `ElementInternals`.
- **Styling:** Set `--pb-size` to change the bank height (84px by default). The bank has four photographed slots and retains its aspect ratio. Set `--pb-page` to a six-digit hex page colour and `--pb-focus` to change the visible focus outline.
- **Reduced motion:** The shared runtime honours `prefers-reduced-motion` by snapping targets and lamps to their final visual state. In this mode the normal impact callback is skipped, so the `bonus` event is currently not emitted; use `change` and `allChecked` for application logic.
- **References:** [API guide](../targets/README.md) · [Live demo](../targets/)

**Implementation notes and limits:**
- The `bonus` event is associated with the target impact animation. Do not make business logic depend on it when reduced motion is enabled; `change.detail.allChecked` is the reliable state signal.
- The group has a maximum of four labels. Keep labels short; the photographed target face has limited space.
- Four targets maximum. Labels are printed inside the photographed target faces; short labels work best.
- In reduced-motion mode, `bonus` is not emitted by the current implementation.

### 6. Drain (`drain`)

- **Implementation source:** [`drain/drain.js`](../drain/drain.js)
- **Standalone bundle:** [`drain/drain.js`](../drain/drain.js)
- **Custom element tag(s):** `<pinball-drain>`
- **Runtime family:** Original mechanical (PinballKit, WebGL scene, artwork and recorded audio)
- **Attributes:**
  - `window`: Number (milliseconds); default `6000`; Observed after connection. Undo duration, read when a delete starts. A value of 0 makes deletion final immediately. Invalid or negative values fall back to 6000ms.
  - `label`: String; default `Delete and undo`; Observed after connection. Accessible name for the control group.
  - `disabled`: Boolean; default Absent; Observed after connection. Makes the host inert and prevents interaction.
- **Properties:**
  - `state` (string, Read-only by convention): Current lifecycle state: `ready`, `draining`, `undoable`, `saving`, or `gone`.
  - `undoWindow` (number, Read-only getter): Effective undo duration in milliseconds.
  - `remaining` (number, Read-only getter): Remaining milliseconds while state is `undoable`; otherwise 0.
- **Methods:**
  - `delete(user = false, initialVel = 180)`: Begin deletion when the control is ready. Use the UI for normal interaction; passing `true` as the first argument emits the `delete` event.
  - `undo(user = false)`: Restore while state is `draining` or `undoable`. Passing `true` emits `undo`.
  - `reset(user = false)`: Serve a fresh ball and return to `ready`. Passing `true` emits `reset`.
- **Events:**
  - `delete`: CustomEvent, `detail: { undoMs: number }`. Fires when a user starts deletion, before the ball finishes draining.
  - `undo`: CustomEvent, empty detail object. Fires when a user restores the item using SHOOT AGAIN.
  - `commit`: CustomEvent, empty detail object. Fires when the undo window expires. With `window="0"`, it fires immediately after deletion.
  - `reset`: CustomEvent, empty detail object. Only emitted when `reset(true)` is called. The normal `reset()` programmatic call is silent.
- **Pointer and touch:** Click the ball/chute or drag the ball downward. SHOOT AGAIN restores the item while the state is `draining` or `undoable`.
- **Keyboard:** The chute and SHOOT AGAIN are native buttons and support normal button activation (Enter/Space). Delete and Backspace on the chute also begin deletion. SHOOT AGAIN is exposed with `aria-disabled` when undo is unavailable; its handler also checks lifecycle state.
- **Forms:** The drain is an action control and does not expose a form value.
- **Styling:** Set `--pb-size` to change the plate height (112px by default). Set `--pb-page` to a six-digit hex page colour and `--pb-focus` to change the visible focus outline.
- **Reduced motion:** The shared runtime honours `prefers-reduced-motion`; the ball moves directly to its state destination, while the undo countdown and lifecycle continue.
- **References:** [API guide](../drain/README.md) · [Live demo](../drain/)

**Implementation notes and limits:**
- The `delete` event occurs at the start of the drain animation. Treat it as the beginning of the undo window, not as proof that the commit has happened.
- After `commit`, the component remains in `gone` until `reset()` is called. The demo page resets it automatically for demonstration purposes.
- After `commit`, the component stays empty until your application calls `reset()`.
- A `window` of 0 removes the undo opportunity and emits `commit` immediately after deletion.

### 7. Pop bumpers (`bumper`)

- **Implementation source:** [`bumper/bumper.js`](../bumper/bumper.js)
- **Standalone bundle:** [`bumper/bumper.js`](../bumper/bumper.js)
- **Custom element tag(s):** `<pinball-bumper>`, `<pinball-bumpers>`
- **Runtime family:** Original mechanical (PinballKit, WebGL scene, artwork and recorded audio)
- **Attributes:**
  - `cap`: String; default `100`; `<pinball-bumper>`. Text printed on the single bumper cap.
  - `points`: Integer; default Parsed from `cap`, else `100`; `<pinball-bumper>`. Explicit points per hit. The first integer parsed from `cap` is used when `points` is not a valid integer.
  - `caps`: Comma-separated strings; default `100,500,100`; `<pinball-bumpers>`. Three cap labels for the cluster; missing entries use the defaults and extra entries are ignored.
  - `label`: String; default `Bonus bumper` / cluster-specific fallback; Both elements. Accessible-name fallback for the relevant control.
  - `disabled`: Boolean; default Absent; Both elements. Makes the host inert and prevents interaction.
- **Properties:**
  - `capText` (string, `<pinball-bumper>`; read-only getter): Current trimmed cap text.
  - `pointValue` (number, `<pinball-bumper>`; read-only getter): Effective points per single-bumper hit.
  - `count`, `score`, `combo` (number, `<pinball-bumper>`; readable state): Total hits, cumulative points, and current combo count.
  - `score`, `hits`, `combo` (number, `<pinball-bumpers>`; readable state): Cluster score, total bumper collisions, and current combo count.
- **Methods:**
  - `launch(targetIdx = -1, user = false)`: `<pinball-bumpers>`; launch a ball. `targetIdx` may be 0, 1, or 2 to aim at a bumper; -1 selects the normal centre-funnel launch.
  - `resetScore()`: `<pinball-bumpers>`; reset `score`, `hits`, and `combo` to 0. It does not cancel balls already in play.
- **Events:**
  - `hit`: `<pinball-bumper>`: `{ index, cap, points, count, score, combo }`. Fires for each pointer or keyboard activation of the single bumper.
  - `hit`: `<pinball-bumpers>`: `{ index, cap, points, count, score, combo, user }`. Fires once for every bumper collision in the cluster. `index` is 0–2; `user` identifies whether the launch came from user activation.
- **Pointer and touch:** The single bumper registers a hit where it is pressed. The cluster launches a ball; pressing over a bumper aims the initial ball toward that bumper. Up to three balls can be active at once.
- **Keyboard:** The single bumper uses a native button. The cluster uses a focusable `div` with `role="button"`. Space and Enter activate both.
- **Forms:** Neither bumper element is form-associated. Treat `hit` as an action event and read the score properties for current totals.
- **Styling:** Set `--pb-size` independently on each element. The single bumper defaults to 72px high; the cluster defaults to 240px. Both retain fixed aspect ratios. Set `--pb-page` to a six-digit hex page colour and `--pb-focus` to change the visible focus outline.
- **Reduced motion:** The shared runtime honours `prefers-reduced-motion`; bumper hits and score changes occur without the ball travel animation.
- **References:** [API guide](../bumper/README.md) · [Live demo](../bumper/)

**Implementation notes and limits:**
- A single bumper derives points from the first integer in `cap` unless a valid integer `points` attribute is provided.
- The cluster is always a fixed triangle of three bumpers. Its `hit` event includes `user`; the single bumper event does not.
- The cluster always contains three bumpers in a fixed triangle.
- Cap text is short by design; long labels may not fit the photographed caps.

## ⚠️ Cross-component contract caveats

- **Toggle:** its `change` event carries the checked state; its `input` event is a plain Event without a `detail` payload.
- **Pop bumpers:** the single bumper and the three-bumper cluster both emit `hit`, but the two variants have different payload shapes.
- **Drop targets:** the `bonus` event is tied to the normal-motion impact callback. Use `change.detail.allChecked` for application logic that must also work with reduced motion.
- **Plunger:** its pull-and-release animation currently continues when reduced motion is requested.
- **Progress:** the indeterminate mode uses a CSS animation and does not currently provide a separate reduced-motion override.
- **Forms:** a form-associated custom element needs browser support for `ElementInternals`. The per-component guide describes the value actually submitted or explains why the control does not submit a form value.
- **File Drop:** selection exposes File objects to the consuming application. The component does not upload files automatically.

## ✅ What this inventory does and does not verify

The source-level checks establish that documented custom-element registrations, observed-attribute declarations, public property/method names and event names are represented in the component specifications. Generated guides, demos, bundles and registry entries are also checked for presence and parity.

This static audit does **not** prove event timing or payload semantics, actual keyboard behavior, form validation/reset behavior, browser compatibility, screen-reader support, or visual quality. Those require the interaction, accessibility, compatibility and release phases in the [release plan](RELEASE-PLAN.md).
