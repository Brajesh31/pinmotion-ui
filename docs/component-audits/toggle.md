## 3. Public API contract

| Member | Current documented behavior | Evidence / status |
|---|---|---|
| checked | Boolean read/write; presence of checked attribute means on | Contract audit and browser regression; passed |
| toggle() | Flips logical state programmatically; no user interaction events | Contract audit; passed |
| checked attribute | Observed after connection; add means on, remove means off | Contract audit; passed |
| disabled | Observed; host becomes inert and visually muted | Existing browser suite checks inert state; broader disabled-state test pending |
| mode | live, plates or 3d rendering mode | Contract audit; passed; visual comparison pending |
| label | Accessible-name fallback, read on connection | New label fallback browser check passed |
| aria-label | Host-provided accessible name forwarded to inner switch button | New browser check passed |
| aria-labelledby | Whitespace-separated IDs resolved from same document/shadow root, then forwarded as inner button name | Computed accessibility-tree checks pass for multiple document IDs and nested ShadowRoot references |
| name / value | Form field configuration; set before connection | FormData checks pass; `form.reset()` restores initial checked state, ARIA and submitted value without user events |
| change | Composed, bubbling CustomEvent with detail { checked: boolean }, for user activation | Existing event contract test; passed |
| input | Plain composed, bubbling Event without detail, immediately after change for user toggle | Contract audit; passed |

Programmatic checked updates deliberately do not emit change/input. The input event has no detail payload. The label and ARIA naming inputs are read at connection and are not observed live.

## 4. Reproduction and fixes

### PM-005: detached property/method access

Before the fix, checked returned undefined before connection and set()/toggle() could access an absent this.btn. Fixed in commit 7ff7e014d6e72319290c55b776622333bc1b5b4f.

Regression coverage: detached checked getter; detached checked setter and toggle(); state/ARIA/FormData after connection; attribute removal; programmatic event suppression. These tests passed in Validate run 44884388345.

### PM-006: accessible name on shadow switch

Before the fix, host aria-label and aria-labelledby did not become the accessible name of the inner button with role=switch. Fixed in commit 4261f5e3d4ed34926a177a08cf51307b031b904b. The resolver now follows aria-labelledby, aria-label, label, then Toggle fallback.

Regression coverage: explicit aria-label, external aria-labelledby and label fallback. All three passed in Validate run [44885328475](https://github.com/Brajesh31/pinmotion-ui/actions/runs/44885328475).


### PM-007: reduced-motion lamp and spring state

The reduced-motion branch previously moved the ball and zeroed its velocity without synchronizing the lamp's logical/visual state or snapping the body spring. The fix sets the ball position, lamp state and spring to their final values. Browser regression checks both on and off transitions while prefers-reduced-motion is active. It passes in Validate run [44892903408](https://github.com/Brajesh31/pinmotion-ui/actions/runs/44892903408).

### PM-008: pointer cancellation and disconnect cleanup

The successful pointer-up path must not run for pointercancel or lostpointercapture. The lifecycle regression uses real CDP touch input to drag, cancel, and remove/reinsert the host during a captured drag. It asserts rollback to the checked state, cleared transient flags, no synthetic change event, and successful activation after reconnection. It passes in Validate run [44892903408](https://github.com/Brajesh31/pinmotion-ui/actions/runs/44892903408).

## 5. Interaction, forms and browser evidence

Validated in headless Chromium 158.0.8127.36 at a 390 CSS px interaction viewport:

- Pointer activation toggles on and emits change.
- Dragging the ball across the lane changes checked state.
- Space and Enter activate the native button role=switch.
- checked state is reflected in FormData when on and removed when off.
- Programmatic state changes do not emit change/input.
- Disabled attribute makes the host inert.
- Disabled fieldset excludes the control from form submission.
- `form.reset()` restores the checked state captured at initial connection, keeps `aria-checked` and `FormData` in sync, and emits no user-interaction events.
- `formStateRestoreCallback` restores checked state and submitted value.
- Keyboard activation leaves the inner button focused with a visible `:focus-visible` outline.
- Disabled pointer and keyboard attempts leave the state and event count unchanged.
- Computed browser AX tree reports role `switch` and correct accessible names for host `aria-label`, multiple `aria-labelledby` IDs, references inside an enclosing ShadowRoot, and the `label` fallback.
- `pointercancel` rolls back the unfinished drag without firing change; removing/reinserting during a drag clears held/pressed state, and the control remains interactive.
- No horizontal overflow at the 390 CSS px viewport.
- WebGL test confirms the Toggle canvas draws non-transparent pixels when WebGL is enabled.

### PM-010: idle WebGL context-loss wakeup

The regression exposed a real recovery gap: when the shared WebGL context was lost while Toggle was idle, the animation loop had stopped and the fallback renderer was not invoked until later user input. The shared PinballKit core now gives connected frame callbacks a wake hook and explicitly wakes connected Toggle instances on context loss. This starts fallback asset loading and drawing without waiting for another interaction.

Validate run [44892903408](https://github.com/Brajesh31/pinmotion-ui/actions/runs/44892903408) passed the dedicated test before any checked-state change:
- WEBGL_lose_context was available and triggered.
- PinballKit.getGL() became null.
- Before changing checked state, Toggle switched to 2d-fallback, marked fallbackReady, and drew 46,793 visible pixels at 436 × 224 backing dimensions.
- Toggle then moved to the on state, lit the lamp, and remained interactive with its normal change event.
- No JavaScript exceptions occurred.

The published screenshot toggle-webgl-context-lost-desktop.png is in [visual artifact 14703031911](https://github.com/Brajesh31/pinmotion-ui/actions/runs/44892903514/artifacts/14703031911). It was opened and visually reviewed; the original photographed lane, chrome ball and lamp remain visible using Canvas 2D.

### PM-009: WebGL-unavailable visual loss

The first captured no-WebGL run proved that Toggle remained interactive but its whole pinball visual disappeared. This is a real rendering defect: the old documentation described it as an accepted loss, but it violates the original-design requirement.

Fix committed in main after the initial failing capture. The new path uses the component's original embedded off/on plates and chrome-ball image in Canvas 2D whenever the shader cannot initialize or `PinballKit.paint` cannot draw, including WebGL context-loss cases. It preserves ball position, lamp crossfade, original colors and artwork; only the live reflective shader is absent.

Dedicated no-WebGL Chromium regression passed in [Validate run 44890886645](https://github.com/Brajesh31/pinmotion-ui/actions/runs/44890886645). It confirmed WebGL really was unavailable, the fallback canvas rendered 46,793 visible pixels at 436 × 224, the off/on plate and ball state changed with `checked`, the normal `change` event still fired, form submission returned the configured value, and there were no JavaScript exceptions. The published no-WebGL screenshot is in [visual artifact 14701533586](https://github.com/Brajesh31/pinmotion-ui/actions/runs/44890886623/artifacts/14701533586). PM-009 is fixed and verified. A forced webglcontextlost event is now separately tested and verified under PM-010.
